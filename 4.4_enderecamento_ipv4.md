# Endereçamento IPv4 — Resumo

## 1. O que é um endereço IP

Um **endereço IP** é um identificador de **32 bits** de uma **interface** de um host ou router.

- Escreve-se em notação decimal com pontos (ex.: `223.1.1.1`), em que cada número (0–255) representa 8 bits.
- `223.1.1.1 = 11011111 00000001 00000001 00000001`.

**Interface** = ligação entre um host/router e uma ligação física.

- **Routers** têm tipicamente **várias** interfaces (logo, vários IPs).
- **Hosts** têm tipicamente **uma ou duas** interfaces (ex.: Ethernet + WiFi).

Ponto-chave: o endereço IP identifica uma **interface**, não o dispositivo inteiro.

---

## 2. Sub-rede

Uma **sub-rede** é um conjunto de interfaces que têm os **mesmos bits de sub-rede** no endereço IP e que **conseguem comunicar entre si sem passar por um router**.

No endereço IP:

- **Bits mais significativos** (à esquerda) = parte de **sub-rede/rede**.
- **Bits menos significativos** (à direita) = parte de **host**.

"Receita" para identificar sub-redes (dos slides):

- Separar cada interface do seu host/router, criando "ilhas" de rede isoladas.
- Cada ilha isolada é uma **sub-rede**.

Exemplo: uma rede com 3 ilhas → `223.1.1.0/24`, `223.1.2.0/24`, `223.1.3.0/24` (máscara `/24`).

---

## 3. Máscara de sub-rede e notação CIDR

**CIDR (Classless InterDomain Routing)**: a parte "sub-rede" do endereço pode ter **comprimento arbitrário**.

Formato: **`a.b.c.d/x`**, onde **x** = número de bits da parte de rede/sub-rede.

```
   Parte "sub-rede"  (x bits)   |   Parte "host" (32 − x bits)
11001000 00010111 0001000 | 0 00000000
                200.23.16.0/23  →  200.23.16.0 a 200.23.17.255
```

- `/x` diz quantos bits, a contar da esquerda, são fixos (a rede).
- Os restantes `32 − x` bits são para os hosts.

---

## 4. Cálculo: número de hosts, endereço de rede e de broadcast

Dada uma sub-rede `a.b.c.d/x`:

- **N.º de hosts possíveis** = 2^(32−x) − 2.
  (Tiram-se 2: o endereço de rede e o endereço de broadcast, que não se atribuem a hosts.)
- **Endereço de rede** = todos os bits de host a **0**.
- **Endereço de broadcast** = todos os bits de host a **1**.

---

## 5. Exemplo resolvido (estilo teste)

> O endereço IPv4 **8.6.4.2** pertence a uma sub-rede com máscara de **18 bits** (`/18`).
> Quantos hosts pode ter? Quais os endereços de rede e de broadcast?

Passo 1 — escrever em binário (só interessa o 3.º octeto, onde "corta" o /18):

```
 8  . 6  .       4        . 2
8  = 00001000
6  = 00000110
4  = 00000100
2  = 00000010
```

`/18` = 8 bits (1.º octeto) + 8 bits (2.º octeto) + **2 bits** do 3.º octeto.

3.º octeto `4 = 00000100`:

```
00 | 000100
↑ rede   ↑ host
```

Passo 2 — **n.º de hosts**: bits de host = 32 − 18 = 14 → 2^14 − 2 = 16384 − 2 = **16382 hosts**.

Passo 3 — **endereço de rede** (bits de host a 0):

```
3.º octeto: 00|000000 = 0
4.º octeto: 00000000 = 0
→ 8.6.0.0
```

Passo 4 — **endereço de broadcast** (bits de host a 1):

```
3.º octeto: 00|111111 = 00111111 = 63
4.º octeto: 11111111 = 255
→ 8.6.63.255
```

**Resposta:** 16382 hosts; rede = `8.6.0.0`; broadcast = `8.6.63.255`.

(Gama de endereços utilizáveis por hosts: `8.6.0.1` até `8.6.63.254`.)

## 6. Como se obtém um endereço IP

São duas perguntas diferentes:

- **Como é que um *host* obtém o seu endereço** (parte "host")?
  - Estaticamente, definido pelo administrador num ficheiro de configuração (ex.: `/etc/rc.config` em UNIX), **ou**
  - Dinamicamente, via **DHCP** (plug-and-play) — ver ficheiro 4.5.
- **Como é que uma *rede* obtém o seu bloco** (parte "rede")?
  - É-lhe alocada uma **porção do espaço de endereços do seu ISP**.

Exemplo de alocação por um ISP com bloco `200.23.16.0/20`:

```
ISP            200.23.16.0/20
Organização 0  200.23.16.0/23
Organização 1  200.23.18.0/23
Organização 2  200.23.20.0/23
...
Organização 7  200.23.30.0/23
```

---

## 7. Endereçamento hierárquico e agregação de rotas

O endereçamento hierárquico permite **anunciar rotas de forma eficiente**.

**Agregação de rotas**: o ISP anuncia ao resto da Internet **um único prefixo** que cobre todas as suas organizações:

- ISP "teo": *"Envia-me tudo o que se destine a `200.23.16.0/20`"* (um anúncio em vez de oito).

**Rotas mais específicas**: se a Organização 1 mudar de ISP (de "teo" para "VOS"), o novo ISP anuncia uma rota **mais específica** só para essa organização:

- "VOS": *"Envia-me `199.31.0.0/16` **ou** `200.23.18.0/23`"*.
- Resultado: como vimos no **longest prefix matching**, ganha sempre o prefixo mais específico (`/23` vence `/20`), por isso o tráfego da Organização 1 passa a ir para o "VOS".

---

## 8. Quem gere os endereços e o problema do esgotamento

- **ICANN (Internet Corporation for Assigned Names and Numbers)** aloca blocos de endereços, através de 5 **Registos Regionais (RR)**, e gere a zona raiz do DNS.
- Os endereços IPv4 são de 32 bits → ~4 mil milhões, **insuficientes**.
- A ICANN alocou a **última fornada de IPv4 em 2011**.
- Soluções: **NAT** (alivia, ver 4.6) e **IPv6** (128 bits, ver 4.7).

---

## Ideia final

Um endereço IPv4 tem 32 bits e identifica uma interface. Divide-se em parte de rede (os `x` bits do `/x`, à esquerda) e parte de host (à direita). Com a máscara consegue-se calcular o endereço de rede (host a 0), o de broadcast (host a 1) e o número de hosts (2^(32−x) − 2). O endereçamento hierárquico (ISP → organizações) permite agregar rotas e anunciá-las eficientemente, com o longest prefix matching a dar prioridade às rotas mais específicas.
