# Algoritmos de roteamento — Resumo

## 1. Objetivo e modelo de grafo

Um **algoritmo de roteamento** calcula os **caminhos de menor custo** entre os routers, para preencher as tabelas de encaminhamento.

A rede modela-se como um **grafo `G = (N, E)`**:

- **N** = conjunto de routers (nós), ex.: `{ u, v, w, x, y, z }`.
- **E** = conjunto de ligações (arestas), ex.: `(u,v), (u,x), (v,x), ...`.
- **`c(x,y)`** = custo da ligação **direta** entre `x` e `y` (`+∞` se não forem vizinhos diretos).

O custo pode ser: sempre 1 (contar saltos), inversamente proporcional à largura de banda, ou diretamente proporcional à congestão.

Relação com o encaminhamento: o **algoritmo de roteamento** determina o caminho ponta-a-ponta; a **tabela de encaminhamento** (que ele preenche) determina o encaminhamento local em cada router.

---

## 2. Classificação dos algoritmos

**Informação global ou descentralizada?**

- **Global** — todos os routers têm informação completa da topologia e dos custos das ligações. → algoritmos **link state**.
- **Descentralizada** — cada router só conhece os vizinhos físicos e o custo das ligações a eles; calcula de forma iterativa, trocando informação com vizinhos. → algoritmos **distance vector**.

**Estáticos ou dinâmicos?**

- **Estáticos** — as rotas mudam lentamente ao longo do tempo.
- **Dinâmicos** — as rotas mudam mais depressa (atualização periódica e/ou em resposta a mudanças nos custos).

# LINK STATE / Dijkstra

## 3. Ideia do Link State

- **Centralizado** no sentido em que cada nó, depois de receber a informação de **todos**, calcula sozinho com a topologia completa.
- Cada router **anuncia (broadcast)** o estado das suas ligações a todos os outros → **todos ficam com a mesma informação** (topologia + custos).
- Com essa informação, cada nó corre o **algoritmo de Dijkstra** para calcular os caminhos de menor custo da sua origem até todos os outros nós.
- É **iterativo**: após `k` iterações, sabe o melhor caminho para `k` destinos.

Notação:

- **`c(x,y)`** — custo da ligação direta de `x` a `y` (`+∞` se não vizinhos).
- **`D(v)`** — estimativa atual do custo do caminho de menor custo da origem até `v`.
- **`p(v)`** — nó **predecessor** ao longo do caminho da origem até `v`.
- **`N'`** — conjunto de nós cujo caminho de menor custo **já é definitivamente conhecido**.

## 4. Pseudocódigo de Dijkstra (origem = u)

```
1  Inicialização:
2    N' = {u}
3    Para todos os nós v:
4      Se v é adjacente a u: D(v) = c(u,v)
5      Caso contrário:       D(v) = ∞
6
7  Ciclo:
8    Encontrar w fora de N' com o menor D(w)
9    Adicionar w a N'
10   Atualizar D(v) para todos os v adjacentes a w e fora de N':
11      D(v) = min( D(v), D(w) + c(w,v) )
12   /* o novo custo até v é o antigo, ou o custo até w mais c(w,v) */
13 Até que N' = N
```

## 5. Exemplo resolvido de Dijkstra

Grafo (custos): `u-v=2, u-x=1, u-w=5, v-x=2, v-w=3, x-w=3, x-y=1, w-y=1, w-z=5, y-z=2`.
Origem = **u**.

| Passo | N' | D(v),p(v) | D(w),p(w) | D(x),p(x) | D(y),p(y) | D(z),p(z) |
|-------|-----|-----------|-----------|-----------|-----------|-----------|
| 0 | u | 2,u | 5,u | **1,u** | ∞ | ∞ |
| 1 | ux | 2,u | 4,x | — | **2,x** | ∞ |
| 2 | uxy | **2,u** | 3,y | — | — | 4,y |
| 3 | uxyv | — | **3,y** | — | — | 4,y |
| 4 | uxyvw | — | — | — | — | **4,y** |
| 5 | uxyvwz | — | — | — | — | — |

(Em cada passo escolhe-se o menor D(·) fora de N' — a **negrito** — e relaxam-se os vizinhos.)

**Árvore de caminhos mais curtos** e **tabela de encaminhamento em u** (1.ª ligação a usar para cada destino):

| destino | ligação a usar |
|---------|----------------|
| v | (u,v) |
| x | (u,x) |
| y | (u,x) |
| w | (u,x) |
| z | (u,x) |

> Como construir a tabela: segue-se o predecessor `p(·)` para trás até `u`; a **primeira aresta** desse caminho é a ligação de saída. Quase tudo sai por `(u,x)` porque o caminho barato passa por x.

## 6. Discussão de Dijkstra

- **Complexidade do algoritmo**: com `n` nós, ~`n(n+1)/2` comparações → **O(n²)** (há implementações O(n·log n)).
- **Complexidade de mensagens**: cada router difunde o seu link state → **O(n²)** mensagens no total.
- **Oscilações** possíveis se o custo da ligação depender do volume de tráfego (o tráfego muda os custos, que mudam as rotas, que mudam o tráfego...).

# DISTANCE VECTOR / Bellman-Ford

## 7. Equação de Bellman-Ford

Base do distance vector (programação dinâmica). `Dx(y)` = custo do caminho de menor custo de `x` até `y`:

```
Dx(y) = min_v { c(x,v) + Dv(y) }
```

- `min_v` — mínimo sobre todos os vizinhos `v` de `x`.
- `c(x,v)` — custo da ligação direta de `x` ao vizinho `v`.
- `Dv(y)` — estimativa que o vizinho `v` tem do custo até `y`.

O vizinho `v` que atinge o mínimo é o **próximo salto** no caminho mais curto até `y`, e é o que vai para a tabela de encaminhamento.

### Exemplo (slide)

Vizinhos de `u` (que são `v`, `x`, `w`) sabem, para o destino `z`: `Dv(z)=5`, `Dx(z)=3`, `Dw(z)=3`. Com `c(u,v)=2, c(u,x)=1, c(u,w)=5`:

```
Du(z) = min{ 2+5, 1+3, 5+3 } = min{7, 4, 8} = 4   (via x)
```

→ Próximo salto de `u` para `z` é **x**.

## 8. Ideia-chave do algoritmo

- De tempo a tempo, **cada nó envia o seu próprio vetor de distâncias aos vizinhos**.
- Quando `x` recebe um novo vetor de um vizinho, **atualiza o seu** com Bellman-Ford:
  `Dx(y) ← min_v { c(x,v) + Dv(y) }` para cada destino `y`.
- Eventualmente, a estimativa `Dx(y)` **converge** para o custo real.

Características: **iterativo, assíncrono, distribuído e self-stopping**:

- Cada iteração local é causada por uma **mudança de custo local** ou por uma **mensagem de um vizinho**.
- Cada nó só **notifica os vizinhos quando o seu vetor muda**. Se nada muda, não envia nada; se não recebe nada, não faz nada.
- Só se troca informação **entre vizinhos** (ao contrário do link state, que difunde para todos).

## 9. Mudança de custos: boas vs más notícias

- **Boas notícias correm depressa**: se uma ligação fica mais barata, a melhoria propaga-se rapidamente.
- **Más notícias correm devagar** → **problema da contagem até ao infinito** (count-to-infinity): quando uma ligação fica muito mais cara/cai, os nós podem ir aumentando o custo aos poucos (6, 7, 8, 9, ...), em ciclo, a confiar em caminhos que já não são bons, demorando a convergir.

## 10. Exemplo resolvido (estilo teste): Bellman-Ford com mudança de custo

Rede com custos: `P-Q=2`, `P-R=1`, `Q-R=6`, `Q-S=3`, `R-S=2`.
O nó **P** tem os vetores (o seu e os dos vizinhos):

```
         P   Q   R   S
D_P = [  0   2   1   3 ]
D_Q = [  2   0   3   3 ]
D_R = [  1   3   0   2 ]
```

O custo da ligação **P–R aumenta de 1 para 12**. P recalcula com Bellman-Ford (vizinhos de P = Q e R; agora `c(P,Q)=2`, `c(P,R)=12`):

```
D_P(P) = 0
D_P(Q) = min{ c(P,Q)+D_Q(Q), c(P,R)+D_R(Q) } = min{ 2+0, 12+3 } = 2    (via Q)
D_P(R) = min{ c(P,Q)+D_Q(R), c(P,R)+D_R(R) } = min{ 2+3, 12+0 } = 5    (via Q)
D_P(S) = min{ c(P,Q)+D_Q(S), c(P,R)+D_R(S) } = min{ 2+3, 12+2 } = 5    (via Q)
```

**Novo vetor:** `D_P = [ 0, 2, 5, 5 ]`.

- O custo para **R** muda de 1 → **5** e deixa de ser direto: passa a ir **via Q** (porque 12 direto é pior que 5 via Q).
- O custo para **S** muda de 3 → **5**, também via Q.

## 11. Link State vs Distance Vector (tabela comparativa)

| | **Link State (LS)** | **Distance Vector (DV)** |
|---|---|---|
| Informação | Global (topologia completa) | Local (só vizinhos) |
| Mensagens | `n` routers → **O(n²)** mensagens difundidas | Troca **só entre vizinhos** |
| Convergência | O(n²); pode ter **oscilações** | Tempo varia; pode ter **loops** e **contagem até ao infinito** |
| Robustez (router avariado/comprometido) | Anuncia custo de **ligação** errado; cada router calcula só a **sua** tabela | Anuncia custo de **caminho** errado ("tenho caminho baratíssimo!") → **black-holing**; o erro **propaga-se** pela rede porque a tabela de um nó é usada por outros |

---

## Ideia final

Os algoritmos de roteamento calculam caminhos de menor custo num grafo. O **Link State** (global) difunde a topologia a todos e cada nó corre **Dijkstra** sozinho. O **Distance Vector** (descentralizado) só troca vetores de distâncias entre vizinhos e converge com a equação de **Bellman-Ford** `Dx(y)=min_v{c(x,v)+Dv(y)}`. O DV é mais leve em mensagens, mas sofre de contagem-até-ao-infinito e propaga erros; o LS é mais pesado mas mais robusto.
