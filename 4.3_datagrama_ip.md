# IP — Formato do datagrama e fragmentação — Resumo

## 1. A camada de rede da Internet

A camada de rede da Internet tem três peças principais:

- **Protocolo IP** — define o formato dos datagramas, o endereçamento e as convenções de tratamento dos pacotes.
- **Protocolo ICMP** — usado para reportar erros e para sinalização entre routers (ex.: "destino inalcançável", mensagens do `ping`/`traceroute`).
- **Algoritmos de seleção de caminho** — protocolos de roteamento (OSPF, BGP) e/ou SDN que preenchem a tabela de encaminhamento.

Resumo:

IP = formato + endereçamento; ICMP = erros/sinalização; roteamento = constrói as tabelas.

---

## 2. O que é o datagrama IP

O **datagrama IP** é a unidade de dados da camada de rede. Tem duas partes:

```
[ Cabeçalho IP ][ Dados (payload) ]
```

O **payload** é tipicamente um segmento TCP ou UDP. O **cabeçalho** transporta toda a informação necessária para encaminhar e tratar o pacote.

---

## 3. Formato do datagrama IPv4 (campo a campo)

O cabeçalho IPv4 tem **20 bytes** (sem opções). Largura de 32 bits por linha:

- **Versão (ver)** — versão do protocolo IP (4 no IPv4).
- **Comprimento do cabeçalho** — tamanho do cabeçalho em bytes (pode variar por causa das opções).
- **Tipo de serviço** — "tipo" de dados, usado para diferenciar tráfego.
- **Comprimento** — comprimento **total** do datagrama (cabeçalho + dados), em bytes.
- **Identificador (16 bits)** — identifica a que datagrama original pertence um fragmento.
- **Flags** — indicam se há mais fragmentos a seguir.
- **Offset de fragmento** — posição deste fragmento dentro do datagrama original.
- **TTL (Time To Live)** — n.º máximo de saltos restantes; é **decrementado a cada router**; ao chegar a 0 o datagrama é descartado (evita pacotes a circular para sempre).
- **Protocolo do nível superior** — a quem entregar o payload (ex.: TCP, UDP). Só é usado no destino.
- **Soma de controlo do cabeçalho (checksum)** — deteta erros no cabeçalho.
- **Endereço IP de origem (32 bits)**.
- **Endereço IP de destino (32 bits)**.
- **Opções (se houver)** — ex.: data/hora, registar a rota tomada, especificar lista de routers a visitar.
- **Dados (payload)** — comprimento variável, tipicamente um segmento TCP/UDP.

Os campos **identificador, flags e offset** servem para a **fragmentação/reconstituição** (ver abaixo).

---

## 4. Overhead

Cada datagrama carrega:

- 20 bytes de cabeçalho TCP
- + 20 bytes de cabeçalho IP
- = **40 bytes** de overhead (mais o overhead da aplicação).

Comprimento máximo de um datagrama: 64 KB. Na prática, tipicamente 1500 bytes ou menos.

---

## 5. MTU

A **MTU (Maximum Transmission Unit)** é o tamanho máximo de dados que cabe numa **trama** do nível de ligação.

- Diferentes tipos de ligação têm MTUs diferentes.
- Se um datagrama IP for maior que a MTU da ligação por onde tem de seguir, tem de ser **fragmentado**.

---

## 6. Fragmentação e reconstituição

**Fragmentação**: um datagrama grande é partido em vários datagramas mais pequenos para caberem na MTU.

- **Entra** 1 datagrama grande → **saem** vários datagramas menores.
- Acontece **na rede** (num router cuja ligação de saída tem MTU mais pequena).
- Os bits do cabeçalho IP (identificador, flags, offset) são usados para **identificar e ordenar** os fragmentos.

**Reconstituição**: juntar os fragmentos para reconstruir o datagrama original.

- Acontece **apenas no destino final** (nunca nos routers do meio).

Frase para decorar:

Fragmenta-se onde for preciso (na rede), mas reconstitui-se só no destino.

---

## 7. Exemplo resolvido de fragmentação

Datagrama de **4000 bytes** (20 de cabeçalho + 3980 de dados), numa ligação com **MTU = 1500 bytes**.

Cada fragmento pode levar no máximo 1500 − 20 = **1480 bytes de payload**. O offset conta-se em unidades de **8 bytes** (1480 ÷ 8 = 185).

| Fragmento | Comprimento | ID | flag (há mais?) | Offset |
|-----------|-------------|----|-----------------|--------|
| 1 | 1500 (1480 dados) | x | 1 | 0 |
| 2 | 1500 (1480 dados) | x | 1 | 185 |
| 3 | 1040 (1020 dados) | x | 0 | 370 |

- Todos têm o **mesmo identificador (x)**, para o destino saber que pertencem ao mesmo datagrama.
- Os 2 primeiros têm **flag = 1** ("ainda vêm mais"); o último tem **flag = 0** ("sou o último").
- Os dados: 1480 + 1480 + 1020 = 3980 bytes ✓ (igual ao payload original).
- Offsets: 0, 1480÷8 = 185, 2960÷8 = 370.

---

## Ideia final

O datagrama IP = cabeçalho + dados. O cabeçalho leva endereços de origem/destino, TTL (decrementado a cada salto), protocolo superior, checksum e campos de fragmentação. Quando um datagrama é maior que a MTU de uma ligação, é fragmentado pela rede e só reconstituído no destino, usando o identificador, as flags e o offset para recompor tudo pela ordem certa.
