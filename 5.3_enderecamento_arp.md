# Endereçamento MAC e ARP — Resumo

## 1. Endereço IP vs endereço MAC

| | **Endereço IP (v4)** | **Endereço MAC** |
|---|---------------------|------------------|
| Bits | 32 bits | **48 bits** |
| Notação | decimal (`128.119.40.136`) | hexadecimal (`1A-2F-BB-76-09-AD`) |
| Nível | rede | ligação |
| Para quê | **encaminhamento no nível de rede** | enviar a trama **localmente**, de uma interface para outra fisicamente conectada (mesma rede) |
| Onde "vive" | configurado (DHCP/estático); depende da sub-rede | gravado na **ROM do adaptador** (às vezes redefinível por software) |
| Estrutura | **hierárquico** (parte rede + parte host) | **plano** |
| Portabilidade | **não portátil** (muda com a sub-rede) | **portátil** (move-se de LAN para LAN) |

Analogias dos slides:

- **Endereço MAC = Número de Segurança Social** (identidade fixa da pessoa).
- **Endereço IP = endereço postal** (depende de onde a pessoa está).

Pontos a reter:

- Cada interface na LAN tem **um endereço MAC de 48 bits único** e um endereço IP
  de 32 bits localmente único.
- A alocação de endereços MAC é administrada pelo **IEEE**; cada fabricante compra
  uma parte do espaço (garante unicidade).

## 2. Exemplo respondido (pergunta-tipo): afirmação verdadeira sobre MAC

> Qual das afirmações sobre endereços MAC é verdadeira?
> a) É atribuído dinamicamente por um servidor DHCP.
> b) Geralmente tem 48 bits e é expresso em hexadecimal.
> c) É roteável e usado para encaminhamento de pacotes na Internet.
> d) Só é suportado por dispositivos da Apple.

**Resposta: b)** — o MAC tem 48 bits e escreve-se em hexadecimal.

- a) Falso — quem é atribuído por DHCP é o **IP**; o MAC vem gravado no adaptador.
- c) Falso — o MAC é **local** (só serve dentro da LAN); quem é roteável é o IP.
- d) Falso — o MAC é universal (gerido pelo IEEE), nada a ver com a Apple.

## 3. ARP — Address Resolution Protocol

Problema que resolve: **como descobrir o endereço MAC de uma interface, sabendo o
seu endereço IP?**

- Cada nó IP (host, router) na rede local tem uma **tabela ARP**.
- Cada entrada: **`< endereço IP ; endereço MAC ; TTL >`**.
- **TTL (Time To Live)**: tempo após o qual a entrada é esquecida (tipicamente
  ~20 minutos).
- Ver no terminal: `arp -n`.

### Funcionamento na mesma rede

Nó **A** quer enviar um datagrama ao nó **B** (sabe o IP de B, mas não o MAC):

1. A **difunde (broadcast)** uma trama de consulta ARP: *"Quem tem o IP `b1.b2.b3.b4`?"*
   - Endereço MAC de destino = **`FF-FF-FF-FF-FF-FF`** (broadcast).
   - Todos os nós da rede local recebem a consulta.
2. **B** reconhece o seu IP e **responde a A** com o seu endereço MAC (resposta
   enviada diretamente para o MAC de A).
3. A recebe a resposta e **guarda a entrada de B na sua tabela ARP**.

O ARP é completamente **plug-and-play**: os nós constroem as tabelas à medida das
necessidades, sem intervenção do administrador.

## 4. Roteamento para outra rede (A → B via router R)

Quando origem e destino estão em **redes diferentes**, a trama é enviada **salto a
salto** até ao router e depois até ao destino. O essencial:

- **Os endereços IP de origem e destino mantêm-se sempre os mesmos** (são os das
  pontas: A e B).
- **Os endereços MAC mudam a cada salto** (identificam só o próximo nó físico).

### Exemplo resolvido (3 passos)

A (`111.111.111.111`, MAC `74-29-...`) envia para B (`222.222.222.222`, MAC
`49-BD-...`) através do router R (interface do lado de A: `111.111.111.110`, MAC
`E6-E9-00-17-BB-4B`; interface do lado de B: `222.222.222.220`, MAC `1A-23-...`).

**Passo 1 — A cria e envia a trama para R:**

```
MAC origem:  74-29-9C-E8-FF-55   (A)
MAC destino: E6-E9-00-17-BB-4B   (R, lado de A)   ← MAC do router, não de B!
IP origem:   111.111.111.111     (A)
IP destino:  222.222.222.222     (B)
```
A sabe que B está noutra rede, por isso põe no campo MAC o do **router** (o seu
gateway), mas mantém o IP de destino como o de **B**.

**Passo 2 — R recebe, extrai o datagrama, decide a interface de saída e recria a
trama para B:**

```
MAC origem:  1A-23-F9-CD-06-9B   (R, lado de B)
MAC destino: 49-BD-D2-C7-56-2A   (B)
IP origem:   111.111.111.111     (A)   ← inalterado
IP destino:  222.222.222.222     (B)   ← inalterado
```

**Passo 3 — B recebe a trama, extrai o datagrama e passa-o ao IP.**

Repara: os **MAC** mudaram em cada salto (A→R, depois R→B), mas os **IP** origem/
destino ficaram sempre `111.111.111.111` → `222.222.222.222`.

## 5. Notas de apoio para perguntas

Quando A envia para outra rede, precisa de duas informações sobre o gateway:

- o **IP do router/gateway** da sua LAN, normalmente configurado manualmente ou recebido por **DHCP**;
- o **MAC desse router**, descoberto com **ARP** dentro da LAN.

Um router, ao receber uma trama:

1. processa a trama de entrada e extrai o datagrama IP;
2. consulta a tabela de encaminhamento IP;
3. escolhe a interface de saída;
4. cria uma nova trama para o próximo salto.

Por isso, ao atravessar routers, os **endereços MAC mudam a cada salto**, mas os **endereços IP origem/destino** continuam a identificar as pontas da comunicação.

---

## Ideia final

O **endereço MAC** (48 bits, hex, gravado no adaptador) é local e plano e serve para
entregar tramas dentro de uma LAN; o **endereço IP** (32 bits, hierárquico) serve
para encaminhar entre redes. O **ARP** traduz IP→MAC dentro da mesma rede, com um
pedido em broadcast e uma resposta direta, guardando o resultado numa tabela ARP. Ao
enviar para outra rede, os **IP origem/destino mantêm-se** ponta-a-ponta, mas os
**MAC mudam a cada salto** (host → router → … → destino).
