# Ethernet — Resumo

## 1. O que é a Ethernet

A **Ethernet** é a tecnologia **dominante** para redes LAN **com fios**.

- Simples e barata.
- Foi a primeira a ser amplamente usada.
- Foi evoluindo em velocidade: de **10 Mbps até 400 Gbps**.
- Um único chip suporta múltiplas velocidades.
- Co-inventada por Bob Metcalfe (Prémio Turing da ACM, 2022).

---

## 2. Topologia física

| **Barramento (bus)** | **Estrela (star)** |
|----------------------|--------------------|
| Popular até meados dos anos 1990 | Prevalece atualmente |
| Todos os nós no **mesmo domínio de colisão** (podem colidir entre si) | No centro, um **switch** ativo de nível 2 |
| | Cada "braço" corre um protocolo Ethernet separado → **os nós não colidem** |

**Domínio de colisão** = conjunto de nós que podem colidir entre si. Na topologia em
estrela com switch, cada ligação é o seu próprio domínio de colisão.

---

## 3. Estrutura da trama Ethernet

```
[ Preâmbulo | MAC destino | MAC origem | Tipo | Dados (payload) | CRC ]
\__________________ Cabeçalho __________________/                \ Rodapé /
```

- **Preâmbulo** — usado para **sincronizar os relógios** do emissor e do recetor
  (7 bytes `10101010` seguidos de 1 byte `10101011`).
- **Endereços MAC de 6 bytes** (origem e destino).
  - Se o adaptador recebe uma trama com o **seu** MAC (ou o broadcast
    `FF-FF-FF-FF-FF-FF`), extrai o payload e passa-o ao nível superior (rede). Caso
    contrário, **descarta** a trama.
- **Tipo** — indica o protocolo do nível superior do payload (tipicamente **IP**).
- **Dados (payload)** — o datagrama encapsulado.
- **CRC (Cyclic Redundancy Check)** — bits para **deteção de erros**. Se for
  detetado erro, a trama é **descartada**.

---

## 4. Modelo de serviço da Ethernet

- **Sem ligação (connectionless)** — não há comunicação prévia (handshaking) entre os
  adaptadores do emissor e do recetor.
- **Não fiável (unreliable)** — o adaptador do recetor **não envia ACK/NAK** ao
  emissor.
  - Os dados de tramas descartadas (ex.: por erro no CRC) só são recuperados se o
    emissor inicial usar **fiabilidade num nível superior (ex.: TCP)**. Caso
    contrário, os dados perdidos ficam perdidos.
- **Acesso ao meio: CSMA/CD** (na Ethernet clássica de meio partilhado):
  - Escutar antes de enviar; se o canal parece livre transmite, se parece ocupado
    espera.
  - Se detetar colisão durante a transmissão: (1) **aborta** e (2) **espera um tempo
    aleatório ("backoff")** antes de tentar de novo.

Frase para decorar:

Ethernet = **sem ligação + não fiável + CSMA/CD**; a recuperação de perdas fica para
o TCP.

---

## 5. Notas de apoio para perguntas

Na Ethernet moderna com **switches** e ligações dedicadas **full-duplex**, as colisões deixam de ser o problema central porque cada ligação funciona como um domínio separado. O **CSMA/CD** é sobretudo associado à Ethernet clássica de meio partilhado.

Se uma trama chega com erro no **CRC**, o adaptador descarta-a. Como Ethernet não envia ACK/NAK, só há recuperação se uma camada superior tratar disso. Com TCP, pode haver retransmissão; com UDP puro, os dados perdem-se, salvo se a aplicação implementar recuperação própria.

O campo **Tipo** e o **CRC** têm funções diferentes:

- **Tipo** — indica o protocolo no payload, por exemplo IP.
- **CRC** — deteta erros na trama.

---

## Ideia final

A Ethernet é a tecnologia dominante de LAN com fios, hoje em topologia em **estrela
com switch** (cada ligação no seu domínio de colisão). A sua **trama** leva preâmbulo,
MAC origem/destino, tipo, dados e **CRC** (deteção de erros → descarta se houver
erro). O serviço é **sem ligação e não fiável** (sem ACK/NAK) — quem garante
fiabilidade é o TCP — e o acesso ao meio na versão clássica é **CSMA/CD** com backoff.
