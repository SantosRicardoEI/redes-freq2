# IPv6 e tunelamento — Resumo

## 1. Porque surgiu o IPv6

- **Motivação inicial**: o espaço de endereçamento de 32 bits do IPv4 estava a caminho da **exaustão** (que veio mesmo a acontecer em **2011**).
- **Motivações adicionais**:
  - Um **cabeçalho mais simples/rápido** acelera o processamento e o encaminhamento.
  - Mudanças ao cabeçalho para **facilitar o suporte a níveis de serviço** (fluxos).

---

## 2. Formato do datagrama IPv6

- **Cabeçalho de tamanho fixo: 40 bytes** (mais simples e rápido de processar que o do IPv4).
- **Não é permitida fragmentação** (ver ponto 4).

Campos do cabeçalho IPv6:

- **Versão (ver)**.
- **Priority (pri)** — identifica prioridade entre datagramas de um mesmo fluxo.
- **Flow label** — identifica datagramas do mesmo "fluxo" (conceito de fluxo não está bem definido).
- **Comprimento do payload**.
- **Next header** — identifica o protocolo do nível superior a quem entregar os dados **ou** o próximo cabeçalho de opções.
- **Hop limit** — equivalente ao TTL do IPv4 (decrementado a cada salto).
- **Endereço de origem (128 bits)**.
- **Endereço de destino (128 bits)**.
- **Dados (payload)**.

---

## 3. Endereços de 128 bits e notação

- IPv6 usa endereços de **128 bits** (3,4 × 10³⁸ endereços).
- Escrevem-se em **8 grupos de 4 dígitos hexadecimais**, separados por `:`.

Forma completa:

```
2001:0db8:0000:0000:0000:8a2e:0070:7334
```

**Regras de abreviatura**:

- Podem-se **omitir os zeros à esquerda** de cada grupo (`0db8` → `db8`, `0070` → `70`).
- Uma **sequência de grupos todos a zero** pode ser substituída por `::`, **mas só uma vez** em todo o endereço (senão ficaria ambíguo quantos grupos foram omitidos).

Forma abreviada do exemplo:

```
2001:db8::8a2e:70:7334
```

Inclusão num URL (com `[ ]`): `http://[2001:db8::8a2e:70:7334]:8080/caminho/pagina.html`.

No DNS, os endereços IPv6 usam registos **AAAA** (em vez de **A**, que é para IPv4).

### Exemplo resolvido (estilo teste): qual NÃO é válido?

```
a) 2001::db8::7334
b) 2001:0:0:db8::7334
c) 2001::db8:0:0:0:7334
d) 2001:0000:0000:0db8:0000:0000:0000:7334
```

- **(a) é INVÁLIDO** — tem **`::` duas vezes**, o que é proibido (ambíguo).
- (b), (c) e (d) são válidos (b e c usam `::` uma só vez; d é a forma completa).

Regra de ouro: **`::` no máximo uma vez por endereço**.

---

## 4. Outras mudanças face ao IPv4

- **Soma de controlo (checksum): eliminada completamente** — para reduzir o tempo de processamento em cada salto. *(É o campo do IPv4 removido no IPv6 para melhorar o desempenho.)*
- **Fragmentação: não permitida** (na rede). Se for preciso, é tratada nas pontas, não nos routers.
- **Opções: permitidas, mas fora do cabeçalho**, indicadas pelo campo **Next header**.

---

## 5. Transição de IPv4 para IPv6: tunelamento

Problema: **nem todos os routers podem ser atualizados ao mesmo tempo** — não há um "flag day" (dia em que tudo muda de uma vez). A rede tem de funcionar com uma **mistura** de routers IPv4 e IPv6.

**Tunelamento**: um datagrama IPv6 é transportado como **payload de um datagrama IPv4** entre routers IPv4 ("um pacote dentro de outro pacote").

```
[ Cabeçalho IPv4 | [ Cabeçalho IPv6 | payload UDP/TCP ] ]
 \________________ Datagrama IPv4 _____________________/
                    \____ Datagrama IPv6 ____/
```

Visão lógica vs física (routers A–B … E–F, todos IPv6, com IPv4 no meio):

- **A → B**: IPv6 normal.
- **B → … → E**: IPv6 **dentro** de IPv4 (origem B, destino E no cabeçalho IPv4 externo) — este é o **túnel**.
- **E → F**: IPv6 normal (E "desembrulha" e recupera o datagrama IPv6 original).

O tunelamento é um conceito muito usado também noutros contextos (ex.: 4G/5G).

---

## 6. Adoção

A adoção tem crescido lentamente: na altura da exaustão do IPv4 (2011), só ~0,25% dos acessos ao Google eram por IPv6; hoje ronda os ~45% (em Portugal, ~42%).

---

## Ideia final

O IPv6 nasceu da exaustão do IPv4 e de querer cabeçalhos mais rápidos. Tem endereços de 128 bits, cabeçalho fixo de 40 bytes, campos novos (flow label, next header, hop limit), **sem checksum** e **sem fragmentação na rede**. Os endereços abreviam-se com `::` (uma só vez). Como a migração não pode ser instantânea, usa-se **tunelamento**: encapsular datagramas IPv6 dentro de IPv4 para atravessar troços que ainda só falam IPv4.
